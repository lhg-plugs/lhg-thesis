# lhg-th-review：盲审模拟

> 目标：在真评审之前，先被"自己人"挑一遍毛病。核心纪律：**用评审的眼光读，而不是用作者的眼光辩护**。
> 诚实说明：模拟评审给不出真实盲审结果，只能提前暴露大概率被挑的问题。

## 1. 何时使用

- 全文初稿完成、查重前自查之后 → 跑全流程
- 导师说"可以送审了"，自己心里没底 → 跑全流程
- 收到真实评审意见要修改 → 用第 5 步的回应策略

## 2. 评审视角清单（四维）

### A. 创新性与学术价值（30 分）
- [ ] 研究问题是否明确、有价值？（不是"正确的废话"问题）
- [ ] 创新点是否真实、可验证？（"预期"与"已实现"分得清吗）
- [ ] 文献综述是否指出了真实缺口？（缺口与研究问题的对应关系）
- [ ] 结论是否超出了"常识"？（只验证常识=工作量，不是创新）

### B. 研究方法与工作量（30 分）
- [ ] 方法是否配得上问题？（方法选择的理由充分吗）
- [ ] 数据是否支撑结论？（样本量、数据来源交代了吗）
- [ ] 实验/调研过程可复现吗？（步骤写清楚了吗）
- [ ] 工作量是否达到学位要求？（硕士/博士标准不同）

### C. 写作与逻辑（25 分）
- [ ] 结构是否完整？（摘要/绪论/方法/结果/结论，首尾呼应吗）
- [ ] 论证是否有证据链？（论点→证据→解释，缺环吗）
- [ ] 图表是否规范、是否被正文引用？（死图、跳号）
- [ ] 语言是否学术、去 AI 味？（对照 lhg-th-writing 第 4 步）

### D. 规范与诚信（15 分，一票否决项）
- [ ] 引用格式是否统一？有无幽灵引用？
- [ ] 有无疑似抄袭段落？（文本重叠率估算）
- [ ] 数据图表是否前后一致？（小数位数、口径）
- [ ] 致谢、声明、原创性声明等学校要求的文件齐了吗？

D 维任何一项严重问题 → 总评直接"不通过"，先修 D 再谈 ABC。

## 3. 打分与结论

| 总分 | 模拟结论 | 行动 |
|---|---|---|
| ≥85 | 大概率通过 | 按意见清单做小修 |
| 70-84 | 可能被要求大修 | 逐条回应，重点修 B/C 维 |
| 60-69 | 大修预警 | 先修结构硬伤，再跑一轮模拟 |
| <60 | 不通过风险高 | 停下来，找导师面谈后再改 |

## 4. 常见盲审意见 Top 10（提前自查）

1. "创新点不明确" → 回第 2 步 A：创新点用事实写，别用形容词
2. "文献综述与研究脱节" → 文献缺口必须对上研究问题
3. "方法论描述不清" → 方法章节按"可复现"标准重写
4. "工作量不足" → 补充实验/数据，或诚实说明边界
5. "结论与研究问题不对应" → 结论章逐条回答绪论的问题
6. "图表不规范" → 图注表注、编号、单位全查一遍
7. "引用不规范/疑似堆砌" → 跑 thesis-cite 专项
8. "语言口语化" → 跑 lhg-th-writing 去 AI 味清单
9. "摘要写得像目录" → 摘要四要素：背景/方法/结果/结论
10. "格式问题多" → 按学校模板逐项对（页眉页脚、行距、字体）

## 5. 收到真实评审意见后的回应策略

1. 逐条编号回应，不许"已修改"三个字打发——写清改了哪里（章节/页码）。
2. 不同意的意见：给理由+证据，语气尊重（"感谢评审专家指出……经核实，本文的处理是……"）。
3. 没法改的（如需要补大实验）：诚实说明限制，写进"不足与展望"，不许硬拗。
4. 修改说明与正文修改对照一遍，防止"说了改了但没改"。

## 6. 反模式（不许这么干）

- ❌ 模拟评分 75 就觉得"稳了"（模拟≠真实）
- ❌ 只改格式不改内容，指望"评审看不出来"
- ❌ 对评审意见逐条顶撞（尊重+证据，不是辩论赛）
- ❌ 收到大修意见后只改皮毛就 resubmit

## 7. 本硕博差异（评审侧重点不同）

| 层次 | 评审最看重 | 可放宽 |
|---|---|---|
| 本科 | 格式规范、逻辑完整、工作量真实 | 创新性（有"思考"即可） |
| 硕士 | 方法得当、数据扎实、有小创新 | 理论深度 |
| 博士 | 原创贡献、理论深度、系统性 | 格式小错（但别太多） |

模拟打分时先确认学位层次，再调权重：本科 D 维权重上调，博士 A 维权重上调。

## 8. 送审前 48 小时清单

- [ ] 全文通读一遍（打印出来读，屏幕上看不出的问题纸上看得出）
- [ ] 图表编号、页码、目录更新
- [ ] 参考文献与正文引用双向对过
- [ ] 摘要、致谢、原创性声明齐了
- [ ] 按学校模板检查页眉页脚、行距、字体
- [ ] 跑一遍 `thesis-audit` + `thesis-cite`，blocker 清零
- [ ] 让同学/朋友读一遍摘要：外行能看懂研究做了什么吗？

## 9. 模拟评审输出模板

```markdown
# 盲审模拟意见（lhg-thesis）
- 学位层次：硕士 / 论文题目：XXX
- 总分：XX/100 → 结论：大概率通过 / 建议大修 / 不通过风险高

## 分维得分
- A 创新性与学术价值：XX/30（失分点：……）
- B 研究方法与工作量：XX/30（失分点：……）
- C 写作与逻辑：XX/25（失分点：……）
- D 规范与诚信：XX/15（一票否决项：无/有→列出）

## 建议修改清单（按优先级）
1. [P0] ……
2. [P1] ……
3. [P2] ……

## Top10 自查对照
- 第 X 条命中：……（已列入修改清单）
```

P0=不改大概率被毙，P1=大概率被问，P2=顺手改。

## 10. 常见问题

- **Q：模拟评审能预测盲审结果吗？** A：不能。它只能暴露"大概率被挑"的问题，真评审的主观因素模拟不了。
- **Q：评出来 65 分怎么办？** A：先看哪一维丢分最多，集中修那一维；修完再跑一轮。不要眉毛胡子一把抓。
- **Q：导师和模拟意见冲突听谁的？** A：听导师的。导师知道你学校的真实标准，模拟给的是通用底线。

## 8. 自检与反馈

**质检门**：
- [ ] 四维清单逐项打过分？
- [ ] D 维（规范诚信）无一票否决项？
- [ ] Top 10 常见意见自查过？
- [ ] 修改清单输出了？（ actionable 的条目，不是"写好一点"）

**标准冒烟用例**：用插件 `fixtures/` 的坏论文跑 structure_audit + 本清单，确认缺章、跳号、高重叠都被指出。

**发现问题**：到本仓库提 issue（标题前缀 `[lhg-th-review]`），描述：论文类型（本/硕）、哪条评审视角拿不准。
